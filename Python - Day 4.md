## Day 4 – File operations: getting data from files

### Why files matter

Up to now, all the data in our programs was typed directly into the code (a list, a string, a dictionary). In real work, data lives **in files** and in other systems: a text file, a spreadsheet, a report. Day 4 is about how Python can **get data out of different kinds of files** (read), **put data into them** (write), and work with it.

> **In plain words:** until now, we wrote our data on a sticky note inside the program. A file is a **drawer on the computer where data is kept**, even after the program has finished. Python can open the drawer, read what is inside, put new things in, and close it again.

### The kinds of files we look at

| File kind | Extension | What it is | Python tool used |
| --- | --- | --- | --- |
| **Text file** | `.txt` | Plain text, line after line | built-in `open()` |
| **Excel file** | `.xlsx` | A spreadsheet with rows and columns | `pandas` (`read_excel`, `to_excel`) |
| **CSV file** | `.csv` | Table data as plain text, values separated by commas | `pandas` (`read_csv`, `to_csv`) |
| **JSON file** | `.json` | Data in `key: value` form, like a Python dictionary | `pandas` (`read_json`) |
| **Parquet file** | `.parquet` | A compressed table format used a lot in big-data work | `pandas` (`read_parquet`) |
| **PDF file** | `.pdf` | Documents: either generated by a system, or scanned pages | libraries such as `pymupdf`, `pdfplumber`, document AI |

We will go through these in the order that you tell me they were taught.

## Day 4 – Text files with `open()`

### Opening a file: modes

`open(path, mode)` opens a file. The **mode** says what you want to do with it:

| Mode | Meaning | If the file does not exist |
| --- | --- | --- |
| `"r"` | **Read** only (default) | Error |
| `"w"` | **Write**: erases the old content first | Created |
| `"a"` | **Append**: adds to the end, keeps the old content | Created |
| `"r+"` | **Read and write** | Error |

> **In plain words:** think of a notebook. `"r"` = you only read it. `"w"` = you tear out all the pages and start fresh. `"a"` = you keep writing on the next empty line. `"r+"` = you can read it and also scribble in it.

### The `with` statement

Always open files with `with`. When the indented block ends, Python **closes the file for you**, even if an error happens.

> **In plain words:** an open file is like an open fridge. `with` is a helper that always shuts the door when you walk away, so you never forget.

### Writing and reading

```python
with open("sample.txt", "w") as f:
    f.write("Hello, this is a sample text file.\n")
    f.write("It has multiple lines.\n")
    f.write("hi hello world\n")
    f.write("hello this is python testing file operations commands")

with open("sample.txt", "r") as f:
    content = f.read()
    print("File content:")
    print(content)
```

Output:

```text
File content:
Hello, this is a sample text file.
It has multiple lines.
hi hello world
hello this is python testing file operations commands
```

`\n` means "new line". `write()` does **not** add it by itself, so you must type it where you want a line to end.

The notebook uses full paths like `/Users/ruchikkota/Desktop/...`, which only exist on the instructor's computer. Use a short name like `"sample.txt"` (saved next to your notebook) or your own path.

### Reading line by line

A file is iterable, so a `for` loop gives one line at a time. `.strip()` removes the `\n` at the end of each line.

```python
with open("sample.txt", "r") as f:
    for line in f:
        print("Line:", line.strip())
```

Output:

```text
Line: Hello, this is a sample text file.
Line: It has multiple lines.
Line: hi hello world
Line: hello this is python testing file operations commands
```

This is the way to read **big files**: only one line sits in memory at a time.

### Reading only a part of the file (from one position to another)

If you want only certain lines, say from line 2 to line 4, you can use a `for` loop with a counter. `enumerate()` gives each line its position, starting at 0.

> **In plain words:** you walk down the lines one by one, ignore the ones before your start, and stop when you reach your end.

```python
start, end = 1, 4          # positions start at 0, end is not included
with open("sample.txt", "r") as f:
    for i, line in enumerate(f):
        if i >= end:
            break
        if i >= start:
            print(i, line.strip())
```

Output:

```text
1 Line 2: It has multiple lines.
2 Line 3: hi hello world
3 Line 4: python testing
```

For small files there is a shorter way: load all lines with `readlines()` and slice the list, exactly like Day 2.

```python
with open("sample.txt", "r") as f:
    lines = f.readlines()
for line in lines[1:4]:
    print(line.strip())
```

Output:

```text
Line 2: It has multiple lines.
Line 3: hi hello world
Line 4: python testing
```

The loop version is better for big files, because it never loads the whole file.

### `"w"` overwrites, `"a"` appends

```python
with open("example.txt", "w") as f:
    f.write("this is boring sessions")
with open("example.txt", "r") as f:
    print(f.read())

with open("example.txt", "a") as f:
    f.write("\nLine 5: This is appended.\n")
    f.write("Line 6: This is python session 5\n")
with open("example.txt", "r") as f:
    print(f.read())
```

Output:

```text
this is boring sessions
this is boring sessions
Line 5: This is appended.
Line 6: This is python session 5

```

Running `"w"` again would wipe everything. Use `"a"` when you want to **keep** what is there.

Small correction: `"a"` does not *update* existing data. It only **adds new text at the end** and leaves what is already there untouched. To change something in the middle, you need `"r+"` with `seek()` (below).

### `read(n)`, `readline()` and `readlines()`

| Method | What it gives you |
| --- | --- |
| `f.read()` | the whole file as one string |
| `f.read(n)` | only the first `n` characters |
| `f.readline()` | one line each time you call it |
| `f.readlines()` | all lines as a **list** of strings |

```python
with open("example.txt", "r") as f:
    print("First 10 characters:", f.read(10))

with open("example.txt", "r") as f:
    print("Line 1:", f.readline().strip())
    print("Line 2:", f.readline().strip())
    print("Line 3:", f.readline().strip())

with open("example.txt", "r") as f:
    print(f.readlines())
```

Output:

```text
First 10 characters: this is bo
Line 1: this is boring sessions
Line 2: Line 5: This is appended.
Line 3: Line 6: This is python session 5
['this is boring sessions\n', 'Line 5: This is appended.\n', 'Line 6: This is python session 5\n']
```

> **In plain words:** the file has a bookmark. Each `readline()` reads one line and moves the bookmark down, so the next call gives the next line.

Note: in the notebook the comment says "First 10 characters" but the code reads 55. The number inside `read()` is what counts.

### Copying a file

Read one file, write to another. One `with` can open both:

```python
with open("example.txt", "r") as src, open("copy_sample.txt", "w") as dest:
    for line in src:
        dest.write(line)

with open("copy_sample.txt") as f:
    print(f.read())
```

Output:

```text
this is boring sessions
Line 5: This is appended.
Line 6: This is python session 5

```

The notebook writes to two copies at once; you just add a second `open(...) as dest1` and a second `dest1.write(line)`.

**Why this matters (ETL):** data engineering pipelines are often **ETL**: **E**xtract (read the data from a source), **T**ransform (clean or change it), **L**oad (write it to a destination). Reading from one file and writing to another, as above, is the smallest version of that idea. The names `src` (source) and `dest` (destination) are just **variable names** that make this clear; they are not special Python functions.

> **In plain words:** it is like copying notes from one notebook into another. The first notebook is the **source**, the second is the **destination**. You read a line from the first and write it into the second, again and again.

### `r+` and `seek()`

`seek(n)` moves the bookmark to position `n` (0 = start of file). In `"r+"` mode, writing **overwrites** the characters at that spot, it does not push the rest along.

```python
with open("example.txt", "r+") as f:
    c = f.read()
    f.seek(0)
    f.write("THIS")

with open("example.txt") as f:
    print(f.read())
print(f.closed)
```

Output:

```text
THIS is boring sessions
Line 5: This is appended.
Line 6: This is python session 5

True
```

`f.closed` is `True`: `with` closed the file for us.

The notebook uses `seek(35)`. The number is a **character position counted from the start of the file** (not a line number), so `seek(35)` puts the cursor at the 35th character. `tell()` tells you where the cursor is now.

```python
with open("example.txt", "r+") as f:
    f.seek(35)
    print(f.tell())
    f.write("chandler bing")

with open("example.txt") as f:
    print(f.read())
```

Output:

```text
35
this is boring sessions
Line 5: Thichandler bing.
Line 6: This is python session 5
```

The new text landed in the middle of line 2 and **replaced** the characters that were there (`s is appended`). That is why `"r+"` needs care.

> **In plain words:** `seek(35)` is like putting your finger on the 35th letter of the page. Whatever you write next starts exactly there.

## Day 4 – Excel, CSV, JSON and Parquet with pandas

These are **table-like** files, so we use `pandas` instead of `open()`. A table in pandas is called a **DataFrame** (rows and columns).

> **In plain words:** a DataFrame is a spreadsheet living inside Python. `read_...` brings a file in, `to_...` saves it out.

```python
import pandas as pd

data = {"Name": ["Alice", "Bob", "Charlie"], "Marks": [85, 90, 78]}
df = pd.DataFrame(data)
print(df)
```

Output:

```text
      Name  Marks
0    Alice     85
1      Bob     90
2  Charlie     78
```

`pd` is just the short name we give pandas with `import pandas as pd`. `pd.DataFrame(data)` turns the dictionary into rows and columns.

**Structured or not?** CSV, Excel and Parquet are **structured** (clear rows and columns). JSON is **semi-structured**: it has keys and values but can be nested and does not need a fixed table shape. Truly unstructured data (free text, images, scanned PDFs) needs other tools.

**Reading each type back into Python** (the function name is always `read_` + the file type):

| File type | Read into a DataFrame | Save from a DataFrame |
| --- | --- | --- |
| CSV | `pd.read_csv("file.csv")` | `df.to_csv("file.csv", index=False)` |
| Excel | `pd.read_excel("file.xlsx")` | `df.to_excel("file.xlsx", index=False)` |
| JSON | `pd.read_json("file.json")` | `df.to_json("file.json")` |
| Parquet | `pd.read_parquet("file.parquet")` | `df.to_parquet("file.parquet")` |

The parquet one is spelled **parquet**, not "packet".

### Excel

```python
df.to_excel("students.xlsx", index=True)
print(pd.read_excel("students.xlsx"))
```

Output:

```text
   Unnamed: 0     Name  Marks
0           0    Alice     85
1           1      Bob     90
2           2  Charlie     78
```

`index=True` also saved the row numbers 0, 1, 2 as a column with no name, so it comes back as **`Unnamed: 0`**. If you do not want it, use `index=False`:

> **In plain words (the `index` setting):** the index is the row number on the left (0, 1, 2...). `index=True` means "also save those row numbers as a new column", which is handy if you want a unique ID for every row. `index=False` means "save only my real columns, no extra numbering column". Most of the time `index=False` is cleaner, because it avoids the `Unnamed: 0` column coming back when you read the file again.

```python
df.to_excel("students2.xlsx", index=False)
print(pd.read_excel("students2.xlsx"))
```

Output:

```text
      Name  Marks
0    Alice     85
1      Bob     90
2  Charlie     78
```

Excel needs the `openpyxl` package installed (`pip install openpyxl`).

### CSV

**CSV** = comma-separated values: a plain text file, one row per line.

```python
df.to_csv("students.csv", index=False)
print(open("students.csv").read())
print(pd.read_csv("students.csv"))
```

Output:

```text
Name,Marks
Alice,85
Bob,90
Charlie,78

      Name  Marks
0    Alice     85
1      Bob     90
2  Charlie     78
```

### JSON

**JSON** stores `key: value` pairs, like Python dictionaries. Very common for data coming from websites and APIs.

```python
df.to_json("students.json", orient="records")
print(open("students.json").read())
print(pd.read_json("students.json"))
```

Output:

```text
[{"Name":"Alice","Marks":85},{"Name":"Bob","Marks":90},{"Name":"Charlie","Marks":78}]
      Name  Marks
0    Alice     85
1      Bob     90
2  Charlie     78
```

### Parquet

**Parquet** is a compressed, column-based format. Files are small and fast to read, so it is the standard in big-data and data-engineering work.

```python
df.to_parquet("students.parquet")
print(pd.read_parquet("students.parquet"))
```

Output:

```text
      Name  Marks
0    Alice     85
1      Bob     90
2  Charlie     78
```

Needs `pip install pyarrow`.

### Which one to use?

| Format | Human-readable? | Size | Typical use |
| --- | --- | --- | --- |
| CSV | Yes (any text editor) | Larger | Simple data exchange |
| Excel | Yes (in Excel) | Medium | Business reports |
| JSON | Yes | Larger | APIs, nested data |
| Parquet | No (binary) | Smallest | Big data, data lakes |

## Day 4 – PDF files

### Two types of PDF

| Type | What is inside | How to read it |
| --- | --- | --- |
| **System-generated PDF** | Real text (an invoice or report exported from software) | Extract the text directly with `pymupdf` or `pdfplumber` |
| **Scanned / image / digital-copy PDF** | A **picture** of a page, no real text | OCR or document AI tools |

> **In plain words:** a system-generated PDF is a typed letter, you can select and copy the words. A scanned PDF is a photo of a letter. The computer sees only pixels, so something has to "read" the picture first.

Both libraries are installed with pip (`pip install pymupdf pdfplumber`). The examples below use a small invoice PDF.

### `pymupdf`

Fast and light. It opens the PDF, and each page can give back its text. It is imported as `pymupdf` (older code says `import fitz`, which is the same library).

```python
import pymupdf

doc = pymupdf.open("report.pdf")
print("Pages:", len(doc))
for page in doc:
    print(page.get_text())
```

Output:

```text
Pages: 1
Invoice 101
Customer: Alice
Total: 250 USD

```

### `pdfplumber`

Slower but better at **layout**: it can pull out text and also **tables**, with positions of words on the page.

```python
import pdfplumber

with pdfplumber.open("report.pdf") as pdf:
    page = pdf.pages[0]
    print("Pages:", len(pdf.pages))
    print(page.extract_text())
    print(page.extract_tables())
```

Output:

```text
Pages: 1
Invoice 101
Customer: Alice
Total: 250 USD
[]
```

`extract_tables()` gives `[]` here because this PDF has no table. If it had one, each table would come back as a list of rows.

|  | `pymupdf` | `pdfplumber` |
| --- | --- | --- |
| Speed | Very fast | Slower |
| Best for | Plain text, many or large PDFs | Tables and exact layout |

### What happens with a scanned PDF?

The same code finds **no text**, because the page is only an image:

```python
import pymupdf

d = pymupdf.open("scanned.pdf")
print(repr(d[0].get_text()))
print(len(d[0].get_images()), "image(s) on the page")
```

Output:

```text
''
1 image(s) on the page
```

Empty text but one image: that is the sign of a scanned PDF.

### Image processing and OCR

For scanned PDFs and images you need **OCR** (optical character recognition), which turns the picture of text into real text. The notebook mentions **Document AI** (Google Cloud's document-processing service); similar tools are Tesseract (free, open source), AWS Textract and Azure Document Intelligence. These also work on photos, scanned forms and receipts, which is why they are used in image processing.

> **In plain words:** `pymupdf` and `pdfplumber` can only read text that is really there. OCR tools look at the picture and guess the letters, like a person reading a photo of a page.

## Day 4 – In my own words (what I understood)

- There are three main things I do with a **text file**: **read** (`"r"`) gets the text out of the file, **write** (`"w"`) puts text in, and **append** (`"a"`) adds more text at the end.
- Before reading or writing, I first have to **open** the file. That is why I use `with open(file_location, mode) as f:`, and then I can read the content with `f.read()`.
- `.strip()` trims the extra white space and the new-line character, which is useful for cleaning each line.
- I can also use a **`for` loop** to go through the file one line at a time, and if I only want a certain part, I can start the loop at one position and stop at another.
- If I use **write** again on a file that already has data, it **clears the old data** and starts again with the new text. To avoid losing the old data, I use **append**, which keeps what is there and writes the new text after it.
- **`readline()`** reads the content one line after another: each call gives me the next line.
- **`readlines()`** reads the whole file and gives me all the lines together as a **list**, so I can print or use them at once.
- In **ETL pipelines** (extract, transform, load) I do simple read and write operations. I can open one file to read (`with open("x.txt", "r") as src`) and another to write (`open("abc.txt", "w") as dest`) in the same `with`, read from the first and write into the second. To copy into more than one document, I just call `dest.write(line)` and `dest1.write(line)`.
- **`"r+"`** is another way to put read and write together: it means read plus write on the same file.
- **`seek()`** moves the cursor. If I give it 35, the cursor moves to position 35 in the file, and whatever I write next starts from there.
- Data can also come as a **CSV, Excel (.xlsx), JSON or Parquet** file. To read these I use `import pandas as pd`, because pandas reads data from structured files.
- `pd.DataFrame(data)` puts the data into **rows and columns**, which is why it is called a DataFrame.
- To read a file I write `pd.read_csv(...)`, `pd.read_parquet(...)`, `pd.read_excel(...)` or `pd.read_json(...)`: the same pattern for every type.
- **`index=True`** adds an extra column with the row numbers (a unique identifier for each row), and **`index=False`** saves the file without that extra column.
- There are **two types of PDF**: **system-generated** (real text inside) and **scanned / image / digital** PDFs (just a picture of the page).
- For system-generated PDFs I can use **`pymupdf`** (fast, plain text) or **`pdfplumber`** (better for tables and layout).
- For scanned PDFs and image processing I need OCR or document AI tools such as **Document AI**.
